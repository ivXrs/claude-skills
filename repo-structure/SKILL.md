---
name: repo-structure
description: generate or refresh repo-structure.md, a tree of the repo's files imported by CLAUDE.md so claude knows the layout without exploring. use to set up the convention in a project, or after adding, removing or renaming files in a repo that has repo-structure.md.
---

# repo structure

## file format
`repo-structure.md` at the repo root:
- a `# repo structure` heading.
- a `<!-- generated by the repo-structure skill: <command> -->` line with the exact tree command, so a refresh reuses its flags.
- the tree output inside a ``` fence.

## generate
pick the command:
- git repo: `git ls-files | tree -a --fromfile . --noreport` (tracked files only). on first creation run `git add -N repo-structure.md` before generating, so the file lists itself.
- no git: `tree -a --gitignore -I .git --noreport`.
- if the tree is over ~300 lines, add `-L 3` and/or `-I 'node_modules|dist|vendor'` (other build or vendored dirs as needed) until it fits.

then write the file:
```
cmd='git ls-files | tree -a --fromfile . --noreport'
{ printf '# repo structure\n\n<!-- generated by the repo-structure skill: %s -->\n\n```\n' "$cmd"; eval "$cmd"; printf '```\n'; } > repo-structure.md
```

## refresh
reuse the recorded command:
```
cmd=$(sed -n 's/^<!-- generated by the repo-structure skill: \(.*\) -->$/\1/p' repo-structure.md)
```
then write the file as in generate. in a git repo, `git add` new files first; `git diff --exit-code repo-structure.md` exits 0 when the tree was already up to date.

## set up a project
when the repo has no `repo-structure.md`:
1. generate the file.
2. add this section to the project's CLAUDE.md (create the file if it doesn't exist):
   ```
   ## repo structure
   @repo-structure.md
   - use this tree to locate files instead of listing or exploring the repo; read only the files the task needs.
   - after adding, removing or renaming tracked files, `git add` them, refresh the tree with the `repo-structure` skill and include it in the same commit.
   ```
3. if CLAUDE.md lists validation to run before committing, add: `repo-structure.md` is up to date (refresh with the `repo-structure` skill).
4. if a readme has a table of paths, add a `repo-structure.md` row in the readme's language (e.g. "generated tree of tracked files, loaded by `CLAUDE.md`.").
5. follow the project's workflow rules (confirmation before edits, `git-workflow` for commits).
